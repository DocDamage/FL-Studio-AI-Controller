## Tests do not establish these claims

No Windows installation, PowerShell execution, actual FL Studio handshake, real
MIDI SysEx exchange, native Win32 Add-menu dispatch, live effect load, plugin
parameter mutation, hotkey registration, audio-interface latency test, local
model inference, RTX 3060 benchmark, or full upstream PostFader suite was executed.
The external pinned dependency could be source-reviewed but not installed in
this environment. The source package therefore includes an explicit Windows
acceptance checklist rather than a fabricated host validation report.

No signed EXE, VST3 binary, downloaded model, MIDI driver or paid plugin is included.
No GitHub repository was created, modified, or pushed for this build.

## Important implementation boundaries

**Supported source paths:** bounded session inspection/fader/pan/name/effect-parameter
control through the V10 adapter; exact preview + approval; durable receipts;
experimental native Windows effect insertion; local audio measurements and separate
WAV/A/B reports; deterministic MIDI export; optional local planner/managed llama.cpp;
nine-tool MCP relay sharing the existing executor.

**Not implemented:** a complete autonomous mix engineer, automatic tonal EQ or
compression decisions, continuous live listening, VST3 audio sensor, automatic FL
render/capture, stem generation/separation, sample-chop arrangement, Playlist or
note editing, plugin reorder/removal, autosave, or guaranteed rollback. “Finish”
authorizes only one displayed pass. Preserve-dynamics mastering is peak-constrained
gain; the other mode is two-pass loudness normalization with possible limiting.

**Windows limitations:** an original named-menu backend has been added, not
live-qualified. It may correctly report unavailable for custom-drawn or localized
FL menus. This is not evidence that all Windows limitations have been eliminated.
